# Autopilot Playbook

Read [earned parallelism](../principles/earned-parallelism.md), [sequence verifiable units](../principles/sequence-verifiable-units.md), [preserve safety](../principles/preserve-safety.md), and the [operating protocol](../references/operating-protocol.md). Use [`patpat-run`](../../patpat-run/SKILL.md) for the durable graph.

Choose a mode from the request:

- **Queue:** independent items, one owner each, root verifies every merge-ready head.
- **Stack:** sequenced items, one linear chain, operator lands unless the request names merge.

## Coordinator protocol

The integration owner is accountable for the objective, validated plan, dependency frontier, inbox, and integration verdict. Unit owners write only their assigned slices. This playbook sequences [`patpat-run`](../../patpat-run/SKILL.md), [`patpat-engineer`](../../patpat-engineer/SKILL.md), and existing provider checks; `program_state.py` stores coordination state but does not spawn, authenticate, wake, monitor, or stop workers, observe providers, or grant delivery authority.

1. **Frame or resume.** If the user asked for the protocol, state the plan and wait for explicit go. For a new multi-unit run, validate the plan and initialize `program_state.py`. When using the durable run graph, initialize `run_state.py` for the objective before recording authority and prohibitions there. Keep dispatch closed until the integration owner admits the frontier. On resume, validate the durable stores against current Git state, then refresh provider-backed PR and check status separately where relevant. Stand down immediately on an explicit stop.
2. **Select and brief.** Run `team_shape.py` from current task evidence and bindings. Split only a `distributed` frontier, use `iterative` serially, and use `adversarial` for falsifiable candidates rather than delivery slices. Pass its `worker_limit` to `set-gate dispatch open --worker-limit <n>`; the state store enforces the limit over recorded assignments in `pending` or `running` state. An optional UTC deadline and integration reserve stop new assignments and reactivations at the dispatch cutoff while current assignments finish and prove. This state cap does not count host processes. Before each assignment or resume, send a standalone brief bound to the `program_id`, `unit_id`, validated `plan_digest`, relevant base and dependency head SHAs, and the authority source for any allowed mutation. Include the unit goal and observable acceptance criterion, relevant repository rules and upstream artifacts, owned and forbidden paths, isolation identity and current generation, exact proof actions and evidence binding, stop conditions, and the `PASS` / `ISSUES` / `BLOCKED` return shape with actual head, changed paths, checks, evidence, deviations, and blockers. Do not dispatch when a required field is unknown or rely on the parent transcript for scope, context, or authority. Assign writable units only to [`patpat-engineer`](../../patpat-engineer/SKILL.md) in separate worktrees or host-enforced sandboxes; overlapping writers run serially. Before recording a head, inspect its actual changed paths against declared ownership.
3. **Build and return.** Each owner implements and proves its slice on the real surface. Owners never ship or merge. A completion report is a candidate, not verification or review. Record worker handoffs as unit inbox events; record program-wide events through the bound integration owner.
4. **Drain and advance.** Treat completion notices as inbox pointers, not interruptions. Drain after a critical section, at dependency or track rollups, and before checkpoints or reports. Use bounded inbox pages. For a unit event, verify its original assignment generation, isolation identity, unit, head, and actual changed paths. For a program-wide event, verify the bound coordinator; for provider-backed notices, independently confirm the source repository, PR, head, and current provider state. The local store is not provider observation. Classify each pointer as a candidate for proof, blocked, stale or reassigned, duplicate/noise, or unresolved liveness. Use only supported unit states; record unresolved liveness in the inbox, decision trail, or report rather than inventing a state. Update the durable state and recompute the frontier; acknowledge a page only after processing succeeds. Dispatch newly eligible work within the worker limit without waiting for unrelated units to become idle.
5. **Verify and prepare delivery.** The integration owner checks dependency ancestry and actual changed paths, then runs [swarm](swarm.md) verification at each current merge-ready head: relevant gates, live behavior on the load-bearing surface, and a diff audit that distrusts the PR body. A new head voids prior verdicts. Findings return to the owner. Run [default delivery](default-delivery.md) for a slice only when delivery authority exists. Keep verification, independent review, and provider readiness as separate gates; a worker self-report or `pr_watch.py` `ready` verdict grants none of them.
6. **Land only with authority.** Merge a green, verified PR only when the request explicitly says `land` or `merge`. Overnight, going to bed, or don't-stop language continues toward merge-ready and then stops. Pause for protected-default merge, production deploy, force-push, secrets, and risky auth or billing changes. Never route around an explicit stop or required authorization.
7. **Reconcile and close.** Use an authoritative read-only host status for worker liveness when available; a transcript, timestamp, or self-asserted actor label is not proof. Assignment generations fence state updates, not old processes. Reject output carrying an old generation; salvage useful findings only through a fresh assignment and fresh proof. If liveness is unknown, quarantine the old writable resource, mark the unit `blocked` only when the current state transition permits it, and continue only in a separate isolated resource. Before reporting completion, drain the inbox, reconcile every dispatched unit to a known outcome or name it unresolved, and verify the completion predicate against current Git/provider heads. Report owners, heads, verdicts, gates, unresolved work, and actual delivery.
