# Autopilot Playbook

Read [earned parallelism](../principles/earned-parallelism.md), [sequence verifiable units](../principles/sequence-verifiable-units.md), [preserve safety](../principles/preserve-safety.md), and the [operating protocol](../references/operating-protocol.md). Use [`patpat-run`](../../patpat-run/SKILL.md) for the durable graph.

Mode: **Queue** (independent items, one owner each, root verifies every merge-ready head) or **Stack** (linear chain; operator lands unless request names merge).

## Coordinator protocol

The integration owner owns the objective, validated plan, dependency frontier, inbox, and integration verdict; unit owners write only their assigned slices. This playbook sequences [`patpat-run`](../../patpat-run/SKILL.md), [`patpat-engineer`](../../patpat-engineer/SKILL.md), and provider checks; `program_state.py` stores coordination state only (it never spawns, monitors, observes providers, or grants delivery authority).

1. **Frame or resume.** If asked for the protocol, state the plan and wait for go. For a new multi-unit run, validate the plan, initialize `program_state.py` (and `run_state.py` if using the durable graph), and keep dispatch closed until the frontier is admitted. On resume, reconcile durable stores with live Git state and refresh provider PR/check status separately. Stand down immediately on explicit stop.
2. **Select and brief.** Run `team_shape.py` from current bindings: split only `distributed` frontiers, run `iterative` serially, and use `adversarial` for falsifiable candidates. Start the current writable program at worker limit 1. Raise it to the `team_shape.py` recommendation only after one pilot unit has fresh verify + review at its current head and the integration owner inspected its actual changed paths (earlier runs do not replace this pilot; integration-owner contract since `program_state.py` does not persist path-inspection receipts). The store caps `pending`/`running` assignments (not host processes); an optional UTC deadline and integration reserve stop new dispatches at cutoff. Send each assignment a standalone brief binding: `program_id`, `unit_id`, `plan_digest`, base/dependency SHAs, authority source, goal, observable acceptance criterion, repo rules/artifacts, owned/forbidden paths, isolation identity + generation, unit timebox, exact proof actions, stop conditions, and `PASS`/`ISSUES`/`BLOCKED` return shape (actual head, changed paths, checks, evidence, deviations, blockers). At timebox expiry, the owner returns partial evidence and the blocker; elapsed time is not authoritative liveness evidence and does not authorize automatic reassignment. Never dispatch with unknown required fields or rely on parent transcripts. Assign writable units only to [`patpat-engineer`](../../patpat-engineer/SKILL.md) in isolated worktrees/sandboxes (overlapping writers run serially); inspect actual changed paths before recording any head.
3. **Build and return.** Owners implement and prove on the real surface, never ship or merge, and post handoffs as unit inbox events (program-wide events go through the bound coordinator). A completion report is a candidate, not verify or review.
4. **Drain and advance.** Treat completion notices as inbox pointers; drain after critical sections, at dependency rollups, and before checkpoints/reports using bounded pages. Verify generation, isolation identity, unit, head, and actual changed paths (and independently confirm provider repo/PR/head/state for provider notices). Classify pointers as candidate, blocked, stale/reassigned, duplicate/noise, or unresolved liveness (log unresolved liveness without inventing unit states). Update store, recompute frontier, ack only after processing succeeds, and dispatch newly eligible units within the limit.
5. **Verify and prepare delivery.** Check dependency ancestry and actual changed paths, then run [swarm](swarm.md) verification at each merge-ready head (gates, live load-bearing behavior, diff audit distrusting PR body). New head voids prior verdicts. Run [default delivery](default-delivery.md) for a slice only with delivery authority and passing `program_state.py check-delivery --unit <id> --checkout <worktree>`. Deliver the whole program only from the tip/final integration unit containing every dependency with whole-system proof ([delivery proof](../../patpat-run/references/delivery-proof.md)). Keep verification, independent review, and provider readiness separate.
6. **Land only with authority.** Merge a verified, provider-passing PR only on explicit `land`/`merge` with passing `check-delivery --gate merge`. After a queue sibling lands, update the next slice onto the new base, record its new head, and re-prove. Overnight/don't-stop stops at merge-ready. Pause for protected-default merge, production deploy, force-push, secrets, and risky auth/billing changes.
7. **Reconcile and close.** Use authoritative read-only host status for worker liveness (transcripts/timestamps are not proof). Generations fence state updates, not old processes: reject stale-generation output and salvage only via fresh assignment + proof. If liveness is unknown, quarantine the old writable resource, mark `blocked` if permitted, and continue only in a fresh isolated resource. Before closing, drain the inbox, reconcile every unit to a known outcome or name it unresolved, and verify the completion predicate against live Git/provider heads. Report owners, heads, verdicts, gates, unresolved work, and actual delivery.
