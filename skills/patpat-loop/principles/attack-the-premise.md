# Attack the Premise

When a proposed solution becomes convoluted, fragile, or burdened with edge-case workarounds, do not patch harder—question the underlying assumptions.

1. Ask whether the problem being solved is actually the real problem or merely a symptom of an upstream design misstep.
2. If two consecutive attempts to solve a problem with the same approach fail or generate cascading complexity, stop. Formulate the core premise explicitly and test it.
3. Challenge self-imposed constraints: Does this really need to run dynamically? Does this really require external state?
4. Reject sunk-cost fallacies. Discarding a flawed premise early saves orders of magnitude more effort than nursing a brittle workaround.
