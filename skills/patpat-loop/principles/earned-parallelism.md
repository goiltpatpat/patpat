# Earned Parallelism

**Rule:** Default mutating work to one owner. Read-only fan-out may share a worktree. Admit arena, swarm, or autopilot writable fan-out only when all gates pass: a recent single-owner run passed the same verifier; a stable verifier judges each deterministic slice; every writable worker has its own worktree or host-enforced sandbox with its own Git index (in Git repos) or isolated filesystem boundary (in non-Git sandboxes), process space, and resource boundary (disjoint files in one worktree are not isolation); one integration owner is named; and whole-system verification covers the integrated result. The current writable program has passed one plan-specific pilot unit at worker limit 1; earlier representative evidence does not replace this pilot. Workers return structured findings and receipts only—no open-ended chatter, no shipping, no auto-merge. For follow-up rounds, retries, or next units, pass a consolidated brief (objective, later directives, prior evidence or branch state) rather than relying on chained interrupt-resumes; reuse a live worker only when it holds expensive process or environment state. Missing isolation (including non-Git workspaces without a host-enforced filesystem sandbox) falls back to serial and says so. Worker output is a candidate; the parent verifies and merges.

Bind a schema-v2 coordinator attestation (`team_shape.py --bind-evidence`) with `{path, sha256, size}` gate bindings before fan-out and rebind on plan, owner, evidence, or isolation changes (schema-v1 cannot admit writable fan-out). Raise worker limit above 1 only after the pilot unit has fresh verify/review at head and the integration owner inspects its actual changed paths. This plan-specific pilot is an integration-owner contract; `program_state.py` does not yet persist or enforce the path-inspection receipt. Optional dispatch deadlines reserve integration time; receipts never grant authority.

**Test:** Verify every gate against the actual worktree, verifier, and resource boundaries before dispatch; if any gate is missing or stale, run serially.
